# Python Builder Design Pattern — WHAT / WHY

## WHAT

### What is the Builder Pattern?

The **Builder Pattern** is a **Creational Design Pattern** that separates the construction of a complex object from its representation. It allows the same construction process to create different versions of an object.

Instead of creating a large object with a complicated constructor full of parameters, the Builder pattern constructs an object **step by step**.

---

### Short Definition

**Builder creates complex objects step-by-step while separating object construction from object representation.**

---

### How it works in Python

In Python, the Builder pattern typically uses:

* An abstract **Builder** class or interface that defines construction steps.
* One or more **ConcreteBuilder** classes implementing those steps.
* A **Director** that controls the order of construction.
* A **Product** object that represents the final result.

Python makes Builder especially interesting because:

* Python supports dynamic typing.
* Objects can be assembled incrementally.
* Optional parameters can become difficult to manage in large constructors.
* Method chaining can create cleaner, more readable code.


## Why should Python developers study the Builder Design Pattern?

### 1. Reduces constructor complexity

Large constructors with many parameters quickly become difficult to read and maintain.

---

### 2. Improves code readability

Step-by-step construction makes object creation easier for developers to understand.

---

### 3. Supports multiple object configurations

The same construction process can create different versions of an object.

Example:

* Gaming computer
* Office computer
* Server computer

using the same building process.

---

### 4. Follows SOLID design principles

Builder helps separate object construction logic from business logic, reducing coupling.

---

### 5. Creates cleaner and more maintainable Python applications

As applications grow, organized creation patterns become easier to modify and extend.

---


Summary

**Builder helps Python developers create complicated objects one step at a time rather than using large constructors.**

**Think of it as following a recipe: same instructions, different final meals.**

# Pattern: Builder

## Participant: Builder

1. Declares the interface that defines each step required to construct a Product.
2. Separates object construction rules from the object's final implementation details.
3. In Python, this is commonly implemented using an abstract base class (`ABC`).
4. The Director calls its methods while ConcreteBuilder supplies the implementation.

---

## Participant: ConcreteBuilder

1. Implements the Builder interface and performs the actual object construction steps.
2. Encapsulates the logic required to create and assemble Product components.
3. In Python, it typically maintains a Product instance and updates it dynamically.
4. It receives requests from the Director and returns the completed Product.

---

## Participant: Director

1. Controls the sequence and order used to build a Product object.
2. Ensures the same construction process can create different Product variations.
3. In Python, it usually stores a Builder reference and invokes build methods.
4. It works with Builder interfaces without depending on specific implementations.

---

## Participant: Product

1. Represents the complex object being assembled during the construction process.
2. Stores all parts and data generated by the Builder steps.
3. In Python, this may be a class whose attributes are assigned incrementally.
4. It receives its completed state from the ConcreteBuilder.

---

## Student Summary

**Builder** → Defines the steps required for object creation.

**ConcreteBuilder** → Performs the actual work of constructing the object.

**Director** → Controls the order in which the object is built.

**Product** → The final completed object returned to the client.
